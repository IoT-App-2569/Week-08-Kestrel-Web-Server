#### กิจกรรมที่ 3 การแปลง C# Object เป็น JSON โดยอัตโนมัติ 

ในระบบ IoT การสื่อสารส่วนใหญ่ใช้รูปแบบข้อมูล **JSON (JavaScript Object Notation)** มาดูกันว่า .NET จัดการเรื่องนี้ให้เราง่ายแค่ไหน

1. เปิดไฟล์ `Program.cs` แล้วเพิ่มโค้ด Endpoint ใหม่เข้าไป **ก่อนบรรทัด `app.Run();`**

2. สั่ง `dotnet run` จากนั้นเปิดเบราว์เซอร์ไปที่  
     `http://localhost:5000/api/status`

3. **สิ่งที่เห็น** หน้าจอเบราว์เซอร์จะแสดงผลเป็น JSON โครงสร้างสมบูรณ์
   ```json
   {
     "gateway": "ESP32-EdgeGateway",
     "status": "Online",
     "uptimeSeconds": 25,
     "isHealthy": true
   }
   ```

#### กิจกรรมที่ 4 การรับค่าผ่าน URL Path (Route Parameters)

เพิ่มฟังก์ชันการรับคำสั่งควบคุม เช่น สั่งเปิด-ปิดหลอดไฟ LED หรือรีเลย์ผ่าน URL

1. เพิ่ม Endpoint ต่อไปนี้ลงใน `Program.cs`
2. ทดสอบเปิด URL บนเบราว์เซอร์
   - ทดสอบพิมพ์ `http://localhost:5000/api/led/on`
   - ทดสอบพิมพ์ `http://localhost:5000/api/led/off`
   - สังเกตผลลัพธ์ JSON ที่ได้รับกลับมา
เพิ่มบรรทัด 
```csharp
	Console.WriteLine($"[{DateTime.Now:HH:mm:ss}] LED Control: {state}");
```
ถัดจากบรรทัด
```csharp
	    string action = state.ToLower() == "on" ? "TURN ON 💡" : "TURN OFF 🌑";   
```
จากนั้นทดลองเปลี่ยนข้อความที่ URL bar แล้วสังเกตุและบันทึกผลที่ terminal
**ผลลัพธ์ที่คาดหวังบนเทอร์มินอล**
```
[xx:xx:xx] LED Control: on
[xx:xx:xx] LED Control: off
```
ผลลัพธ์ที่ได้
~~~
[09:04:39] LED Control: on
[09:04:51] LED Control: off
~~~

## ภารกิจท้าทาย (Micro-Challenge)

ให้นักศึกษาเขียน Endpoint ของตัวเองเพิ่มลงใน `Program.cs` ตามเงื่อนไขดังนี้
1. ตั้งชื่อ Path ว่า `/api/student`
2. เมื่อเปิดเข้าไปดู จะต้องคืนค่า JSON ที่มีข้อมูลดังต่อไปนี้
   - `studentId` = รหัสนักศึกษาของตนเอง (ชนิดสตริง)
   - `studentName`= ชื่อ-นามสกุลภาษาอังกฤษของตนเอง
   - `faculty`= คณะและสาขาวิชาที่กำลังศึกษา
   - `targetSensor`= ชื่อเซนเซอร์ที่ตนเองสนใจนำมาต่อกับ ESP32 ในวิชานี้ (เช่น "DHT22", "Potentiometer", "MQ-2")
   - `timestamp`= เวลาปัจจุบันของเซิร์ฟเวอร์ (`DateTime.Now.ToString(...)`)

 **หลักฐานการส่งงาน** บันทึกภาพหน้าจอเบราว์เซอร์ที่เปิดแสดงผล JSON จาก `/api/student` พร้อมโค้ดใน VS Code ลงในรายงานผลการทดลอง

## คำถามท้ายการทดลอง (Review Questions)
1. ในสถาปัตยกรรมของ Kestrel ตัวแปร `builder` ทำหน้าที่อะไร และตัวแปร `app` ทำหน้าที่อะไร
~~~
builder ทำหน้าที่กำหนดค่าเริ่มต้นก่อนสร้างแอป เช่น ลงทะเบียน Service, ดึงค่าการตั้งค่าคอนฟิกต่าง ๆ และเตรียมระบบ Kestrel Server ให้พร้อมทำงาน
app ถูกสร้างขึ้นมาจาก builder ทำหน้าที่คอยรับ-ส่งข้อมูล กำหนดเส้นทาง URL และสั่งเริ่มรันเซิร์ฟเวอร์ด้วยคำสั่ง app.Run()
~~~
2. เปรียบเทียบความสะดวกระหว่างการสร้าง Web Server บน .NET Minimal API กับการรันผ่าน LAMP Stack (Apache + PHP) ว่ามีข้อดีข้อเสียต่างกันอย่างไรในมุมมองของงาน IoT Gateway
~~~
.NET Minimal API:
ข้อดี: เบาและทำงานได้เร็วมาก มี Kestrel Web Server ในตัว ไม่ต้องติดตั้งโปรแกรมเพิ่ม แปลงข้อมูลเป็น JSON อัตโนมัติ
ข้อเสีย: ต้องติดตั้ง .NET Runtime หรือคอมไพล์โค้ดก่อนนำไปรันบนอุปกรณ์
LAMP Stack (Apache + PHP):
ข้อดี: เขียนเสร็จแก้ไขไฟล์สคริปต์หน้างานได้ทันที มีตัวอย่างและไลบรารีให้ดูเยอะ
ข้อเสีย: ติดตั้งหลายส่วนประกอบ ทำให้หนักเครื่อง กินแรมและ CPU สูงกว่า ไม่คล่องตัวเท่าสำหรับอุปกรณ์ IoT ที่มีทรัพยากรจำกัด
~~~
3. นักศึกษาคิดว่าการเพิ่ม `/api/` เข้าไปใน route นั้นมีประโยชน์อย่างไรบ้าง ถ้าไม่ใส่จะเกิดปัญหาอะไรบ้าง
~~~
ประโยชน์
- ช่วยแบ่งแยกหน้าที่ชัดเจนระหว่าง URL ที่ใช้ส่งข้อมูลดิบ (JSON/Data) ให้อุปกรณ์ IoT กับหน้าเว็บปกติ (HTML/UI) ที่เปิดดูบนเบราว์เซอร์
- กำหนดสิทธิ์ความปลอดภัยหรือแยกเวอร์ชันของระบบในอนาคตได้ง่าย 
ปัญหาหากไม่ใส่
- เกิดการชนกันของชื่อหน้าเว็บ (Route Collision) เช่น มีหน้าแดชบอร์ดชื่อ /status ซ้ำกับจุดส่งข้อมูลดิบ /status
- จัดการระบบยากถ้าโปรเจกต์มีขนาดใหญ่ขึ้น เพราะไม่สามารถแยกประเภท Request ได้ชัดเจนตั้งแต่แรก
~~~

#### [Checkpoint 2.1 ทดสอบความเข้าใจ]
1. ใน ESP-IDF v6.x ฟังก์ชัน `adc_oneshot_read()` คืนค่าผลลัพธ์เป็นตัวเลขแบบใด และมีช่วงค่าต่ำสุด-สูงสุดเท่าใดเมื่อตั้งค่าเป็น `ADC_BITWIDTH_12`
   - **คำตอบ:**
   ~~~
   คืนค่าผลลัพธ์เป็นตัวเลขจำนวนเต็ม (Integer) ช่วงค่าต่ำสุดคือ 0 และสูงสุดคือ 4095
   ~~~
2. ทำไมเราจึงต้องกดปุ่ม `Ctrl + ]` เพื่อปิด **ESP-IDF Monitor** ก่อนที่เราจะรันโปรแกรมฝั่ง C# Kestrel ในใบงานถัดไป
   *(คำใบ้: หากโปรเซส idf.py monitor ยังเปิดค้างอยู่ จะเกิดอะไรขึ้นกับพอร์ต COM)*
   - **คำตอบ:**
   ~~~
   เพื่อยกเลิกการครอบครองและปลดล็อกพอร์ตสื่อสารอนุกรม เพราะระบบปฏิบัติการอนุญาตให้มีเพียงโปรเซสเดียวเข้าถึงพอร์ต COM นั้นๆ ในเวลาเดียวกันได้
   ถ้าไม่ปิด Monitor ก่อน โปรแกรมฝั่ง C# จะไม่สามารถเปิดพอร์ตเพื่ออ่านข้อมูลได้และจะเกิดข้อผิดพลาด Access Denied / Resource Busy ทันที
   ~~~

#### 📋 [Checkpoint 3.1: ทดสอบกลไก Fallback Simulation]
1. ขณะที่โปรแกรม C# กำลังรันอยู่ ให้ถอดสาย USB ของ ESP32 ออกจากคอมพิวเตอร์

   - ค่า `dataSource` เปลี่ยนเป็นอะไร?
   - ค่า `rawValue` ยังเปลี่ยนได้อยู่หรือไม่ และเปลี่ยนในลักษณะใด?
   - **คำตอบ:**
   ~~~
   ค่า dataSource จะสลับเป็น "Simulation Mode (Sine Wave)" อัตโนมัติ และค่า rawValue ยังเปลี่ยนแปลงได้ต่อเนื่อง
   โดยจะแกว่งขึ้น-ลงเป็นลูกคลื่นตามฟังก์ชัน Sine Wave ในช่วง 0 ถึง 4095 ทำให้ระบบยังคงทำงานต่อได้โดยไม่ล่ม (Fault Tolerant)

## 🎯 ภารกิจท้าทาย (Micro-Challenge)
- ให้นักศึกษาเพิ่มฟิลด์ `alertLevel` เข้าไปในผลลัพธ์ JSON ของ `/api/telemetry`:
  - ถ้า `percentage` มากกว่า 85.0% ให้ส่งค่า `"DANGER (HIGH)"`
  - ถ้า `percentage` ระหว่าง 70.0% - 85.0% ให้ส่งค่า `"WARNING"`
  - ถ้า `percentage` ต่ำกว่า 70.0% ให้ส่งค่า `"NORMAL"`
- บันทึกภาพหน้าจอเบราว์เซอร์ขณะหมุนไปที่ระดับต่างๆ เพื่อแสดงว่าฟิลด์ `alertLevel` ทำงานถูกต้อง
